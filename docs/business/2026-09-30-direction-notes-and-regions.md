# 產品方向：找房筆記 × 生活圈

日期：2026-09-30
狀態：**已定案的方向**（使用者確認）。細節與順序可再調，方向以這份為準。
相關：`2026-09-30-subscription-and-legal.md`（訂閱與法律評估）、`../design/2026-09-20-architecture.md`（原始架構）

---

## 1. 一句話

從「有房源的租屋地圖」改成「**找房筆記**」：房源由使用者自己帶進來，產品賣的是對一個地址的分析（通勤、行情、每月支出、生活機能、災害、治安）與整理決策的工具。不再每天抓 591。

## 2. 為什麼轉向

- 共用的爬蟲房源庫是最大法律風險。公平會公處字第 106084 號罰的「豬豬快租」是免費 App：問題不在收不收費，而在用抓來的房源做替代服務。
- 我們真正的差異本來就不在房源，在分析層，而分析層全部建在可商用的開放資料上（政府開放資料、TDX、OSM）。
- 省掉採集機、每日排程、喚醒 / 睡眠、好房限速這一串維運。

## 3. 已決定的事

| 決定 | 內容 |
|---|---|
| 產品定位 | 找房筆記。入口是「評估一個地址」，存下來才是筆記 |
| 591 / 好房每日採集 | **停止**。排程 `RentmapSync-*` 已停用（2026-09-30），不進正式站 |
| 現有抓來的資料 | **只留在使用者本機的 D1**，不上傳、不部署 |
| 範圍 | 以**六都**為主，不一次做全台 |
| 分區 | 以**生活圈**切，不用北中南（見第 4 節） |
| 檔案 | 不存任何檔案（沿用既有決定） |

## 4. 生活圈

用通勤範圍切，不用地理方位切。台南與高雄相隔四十多公里、幾乎沒有跨市通勤，綁成「南」只會讓路網與資料量加倍。

| 代碼 | 名稱 | 範圍 | 備註 |
|---|---|---|---|
| `north` | 北北基桃 | 台北市、新北市、桃園市、基隆市 | 跨市通勤多，必須同一區。基隆不是六都但通勤上是一體 |
| `taichung` | 台中 | 台中市 | 之後視需要加彰化 |
| `tainan` | 台南 | 台南市 | |
| `kaohsiung` | 高雄 | 高雄市 | |

**使用者看到的**：第一次進來問「你要找哪裡的房子」，列城市讓他選一個，系統對應到生活圈。

**規則**
- 生活圈是**偏好設定**，隨時可切換，不鎖帳號。切換後筆記、地點都保留。
- 房源與「我的地點」**依座標歸區**，不用使用者自己標。
- 一次只載入一個生活圈的資料：地圖範圍、行政區選單、篩選、通勤路網都跟著生活圈走。
- 資料一區一區上線，每區有自己的完成度（資料狀態頁依生活圈顯示）。

**上線順序**：`north` → `taichung` → `kaohsiung` → `tainan`。北區最先，因為雙北資料已齊，只要補桃園與基隆。

## 5. 產品流程怎麼變

### 5.1 入口：地址即報告
零房源時產品也要好用。輸入地址或在地圖點一下 → 出完整報告（通勤、行情、每月支出、機能、災害、治安）。按「存成筆記」才進收藏與看板。目前的「右鍵看附近」（`features/map/PointDetail`）就是雛形，要升成主流程。

### 5.2 房源怎麼進來

| 方式 | 公開版 | 說明 |
|---|---|---|
| 手動填寫 | 做 | 必填只要地址（或地圖上點）、租金、坪數、房型；其他都能從位置算 |
| 瀏覽器書籤小工具 | 做 | 使用者在 591 等頁面按一下，由**他自己的瀏覽器**讀出事實欄位送過來；伺服器不碰外站 |
| 貼網址由伺服器代抓 | **不做** | 灰色地帶（591 條款禁止程式擷取）；律師確認前不做 |
| 每日自動採集 | **不做** | |

只存**事實**：租金、坪數、樓層、格局、地址 / 座標、電梯、寵物、開伙、管理費、水電計價、來源連結。
不存：照片、屋況介紹文字（著作）、房東 / 仲介姓名電話（個資）。面板改成「原始頁面」連結。

### 5.3 每人各自一份
現在的 `properties` / `listings` 是所有人共用的一份。公開版改成每個使用者只看得到自己的。

### 5.4 私人模式開關
一份程式碼、兩種行為，用環境變數切（暫名 `PRIVATE_POOL`）：
- **開**（只在使用者本機）：照舊顯示共用的 591 房源池、照片、聯絡人，採集 CLI 可用。
- **關**（正式站預設）：每人只看到自己的筆記，上述欄位與 `/api/ingest/listings` 都不存在。

### 5.5 會失去資料的功能

| 功能 | 處理 |
|---|---|
| 每坪開價圖層、行情卡「目前開價」 | 公開版拿掉，行情只靠實價登錄 |
| 降價標記、刊登天數、下架偵測 | 公開版拿掉（私人模式保留） |
| 拉麵圖層的 Google 評分 | 公開版拿掉評分，只留店名與位置 |

## 7. 要重新設計的三件事

1. **通勤引擎分區載入**。現在把雙北公車網路整份放進 Worker 記憶體（`src/worker/transit/network.ts`），全台放不下。改成依生活圈各一份，快取 key 帶生活圈。
2. **機車 / 開車通勤時間**。雙北以外大眾運輸稀疏，多數人騎機車。沒有這個，通勤功能在中南部沒有意義。**這是台中開區的前置條件。** 初版可用路網距離 × 平均時速估，之後再接路徑引擎。
3. **拿掉寫死的雙北**。目前約 30 個檔案寫死「台北市 / 新北市」或雙北範圍：`src/shared/constants.ts`（CITIES、DISTRICTS）、`schemas.ts`（city enum）、`address.ts`、`market.ts`、`hazard.ts`、地圖的 `TW_BOUNDS`、各 collector 的城市清單等。改成由一份生活圈定義（`src/shared/regions.ts`）驅動。

## 8. 實作順序

| 步驟 | 內容 | 為什麼在這個位置 |
|---|---|---|
| 1 | 生活圈定義檔 + 拿掉寫死的雙北（行為不變，仍只有 `north` 的雙北） | 之後每一步都依賴它 |
| 2 | 房源改成每人各自一份 + 私人模式開關；公開模式拿掉照片、屋況文字、聯絡人 | 法律文件的第一項待辦，也是轉向的前提 |
| 3 | 「地址即報告」主流程 + 存成筆記 | 零房源時產品就有價值 |
| 4 | 瀏覽器書籤小工具 | 降低輸入成本 |
| 5 | 北區補桃園、基隆；加台鐵 | 第一個完整的生活圈 |
| 6 | 機車 / 開車通勤時間 | 台中開區的前置條件 |
| 7 | 通勤引擎分區載入 → 開台中 → 高雄 → 台南 | 每區照第 6 節清單補資料 |
| 8 | 條款、同意流程、金流、部署（見訂閱與法律文件） | 律師看過條款再收費 |

### 進度(2026-09-30)

1–6 完成;7 的程式完成(引擎分區載入、匯入分區覆蓋、縣市界、台中與高雄捷運),台中 / 高雄 / 台南要在家抓資料後開區,步驟見 `../design/2026-09-30-open-a-region.md`;
8 完成條款頁、同意流程、帳號匯出 / 刪除,金流與部署未做(等律師與「好」)。

**2026-10-01**:7 完成 — 台中 / 台南 / 高雄的資料都抓齊、三個生活圈已打開並在本機驗證過(`../design/2026-09-30-open-a-region.md` §4);雲端可做的事列在 `../design/2026-10-01-cloud-tasks.md`。

## 9. 還沒決定的事

- 介紹頁與對外名稱要不要跟著改（現在叫「租屋筆記」，方向其實已經吻合）。
- 彙總統計（行政區 × 房型 × 月的刊登價趨勢）要不要做：資料來源是已停止的每日採集，目前傾向不做。
- 免費版與訂閱版的功能切分，在「沒有共用房源池」之後要重看一次（原表的收藏上限、地點數仍適用）。
- 機車通勤初版用直線距離估，還是一開始就接路徑引擎。
